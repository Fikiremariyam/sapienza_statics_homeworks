Homework 1 · Cryptography

Private key → public key

Elliptic-curve scalar multiplication as a one-way function: a toy curve, the algorithm step by step, and a statistical look at its outputs.

01

Assignment

Practical. Write a small JavaScript / HTML / CSS program showing how a private key generates a public key through elliptic-curve scalar multiplication (in Ethereum the curve is secp256k1). Use the toy curve y² = x³ + 7 (mod 17), base point G = (1, 5) and private key k = 6; implement point addition, print G, 2G, …, kG (or use a faster method) and print the result as the toy public key. Optional: a slowed-down visual representation of the algorithm.

Statistical exploration. Repeat with different k and base points; study the distribution of coordinates, value frequencies, bit distribution, uniformity, input/output correlation and avalanche-like behaviour; discuss which properties matter for a one-way function and which belong to hash functions.

Research. Modern applications of cryptography and statistics in the most famous blockchains.

02

Theory

An elliptic curve over a prime field 𝔽ₚ is the set of pairs (x, y) with y² ≡ x³ + ax + b (mod p), plus a special point at infinity O. Ethereum and Bitcoin use secp256k1, where a = 0, b = 7 and p = 2²⁵⁶ − 2³² − 977. Our toy curve has the same equation, only with p = 17.

Points can be added. Geometrically, the line through P and Q meets the curve in a third point, and the sum is that point reflected over the x-axis. Algebraically, with every operation done mod p:

P ≠ Q: λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ P = Q: λ = (3x₁² + a) · (2y₁)⁻¹ (point doubling) x₃ = λ² − x₁ − x₂ y₃ = λ(x₁ − x₃) − y₁

If Q = −P (same x, opposite y), the result is O, which acts as zero: P + O = P. The "division" is a multiplication by a modular inverse, computed here with the extended Euclidean algorithm.

Scalar multiplication means adding G to itself k times: Q = kG = G + G + … + G. Doing it naively costs k − 1 additions. The double-and-add method reads k in binary and, for each bit, doubles the running point and adds G when the bit is 1. That takes about log₂k steps, so 256-bit keys are practical.

The repeated multiples of G cycle through a subgroup whose size is the order n of G (nG = O), so the private key only matters modulo n. Going forward (k → kG) is fast. Going backward (kG → k) is the Elliptic Curve Discrete Logarithm Problem (ECDLP), and for a 256-bit group no known algorithm solves it in practical time. This asymmetry is what makes k ↦ kG a one-way function. In Ethereum, k is the private key and Q = kG is the public key, from which the address is derived (Homework 1.2).

Discussion

Scalar multiplication shares some behaviour with a hash function: it is deterministic, fast forwards and hard to invert. Its algebraic structure, however, is the opposite of what a hash is designed to have.

The meaningful properties for k ↦ kG are determinism, efficiency and hardness of inversion. Its security rests on the size of the group and the hardness of the ECDLP, not on how random its outputs look. Uniform bits, absence of correlation and avalanche behaviour are hash-function properties. A hash is supposed to behave like a random oracle with no exploitable structure, while scalar multiplication is valuable precisely because of its structure: Alice's a(bG) equals Bob's b(aG), which is how two parties agree on a key.

The toy curve also shows why real curves are chosen carefully. Its group has 18 points, and the order 18 = 2 · 3² is not prime, so some base points generate tiny subgroups. (3, 0) has order 2, so it only ever produces (3, 0) and O. G = (1, 5) has order 9, so only 9 private keys are distinct. secp256k1 instead has a prime order n (cofactor 1), so every non-identity point generates the whole group.

09

Research: cryptography and statistics in major blockchains

Bitcoin

Accounts are secp256k1 key pairs. Spending is authorised by an ECDSA signature, and since the 2021 Taproot upgrade also by Schnorr signatures (BIP-340), which can be aggregated. Blocks are chained by double SHA-256, and transactions in a block are summarised by a Merkle tree. Proof-of-work mining is a statistical process: every hash is an independent trial with a tiny success probability, so block discovery is approximately a Poisson process. Inter-block times are roughly exponential with a 10-minute mean, and the difficulty is re-estimated every 2016 blocks to keep that mean. Nakamoto's whitepaper uses a Poisson / gambler's-ruin argument to compute the probability that an attacker with a minority of hash power could rewrite z confirmed blocks, which shrinks exponentially in z.

Ethereum

User accounts also use secp256k1 ECDSA. Addresses are the last 20 bytes of the Keccak-256 hash of the public key, with EIP-55 checksums. Since the 2022 Merge, Ethereum uses proof of stake: validators sign with BLS signatures on the BLS12-381 curve so thousands of signatures can be aggregated into one, and block proposers are chosen pseudo-randomly using RANDAO, a mix of validator-contributed randomness. Data storage uses Merkle-Patricia tries, and blob data (EIP-4844) uses KZG polynomial commitments. Layer-2 rollups use zero-knowledge proofs (SNARKs/STARKs) to prove batches of transactions are valid. The EIP-1559 fee market also adjusts the base fee statistically from how full recent blocks were.

Other chains

Solana signs with Ed25519 and orders events with "Proof of History", a sequential SHA-256 chain used as a verifiable clock. Monero hides senders with ring signatures and amounts with Pedersen commitments. Statistics directly affect its privacy: decoy outputs are sampled from a distribution fitted to real spending ages, because researchers showed that badly chosen decoys let the real input be guessed.

Statistics as an attack tool

Statistics is also used against blockchains. Chain-analysis firms cluster addresses using heuristics (such as common-input ownership) and timing patterns. Weak randomness in signature nonces has let attackers recover private keys, since reusing an ECDSA nonce reveals the key. Tests like the ones on this page (bit balance, uniformity) are how weak key generators get caught.
