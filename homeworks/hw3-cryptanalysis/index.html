Encryption & cryptanalysis

One message, two ciphers: elliptic-curve ElGamal on secp256k1 and the Caesar shift. Each is then broken, one with letter statistics and the other by searching its small key space.

01

Homework

  1. Using the toy secp256k1 scheme from Homework 1, encrypt and decrypt a simple message; describe the steps and the role of the keys.
  2. Implement the Caesar cipher on the same message, and compare the two schemes (procedures, key spaces, statistical properties).
  3. Statistical cryptanalysis: recover the Caesar key from letter statistics of a known language; test on ciphertexts of different lengths; optionally compare exhaustive search, letter frequency and n-gram scoring.
  4. The toy scheme restricts the private key to a small range: attack it, compare with the Caesar attack, explain why it fails against a properly sized key, and discuss which weaknesses come from the small key space and which from the toy design.
02

Toy ECC encryption (EC-ElGamal on secp256k1)

We use the real secp256k1 curve and generator G from Homework 1. The only "toy" restriction is that the private key d is limited to a small range 1 … 2b.

Key generation d ∈ [1, 2ᵇ] (private) Q = d·G (public) Encoding character code m ∈ [0, 255] → point M = m·G Encryption pick a fresh random r, C₁ = r·G, C₂ = M + r·Q Decryption M = C₂ − d·C₁ (because d·C₁ = d·r·G = r·Q) Decoding find m with m·G = M (lookup table of 256 points)

The role of the keys. The public key Q lets anyone encrypt: they mask M with r·Q, which only they can compute because only they know r. The private key d is the only thing that removes the mask, since d·C₁ = r·Q. The ephemeral key r is new for every character, so the same letter encrypts differently each time (the scheme is probabilistic). The security of the whole scheme relies on recovering d from Q (the ECDLP) being hard.

03

The Caesar cipher

Each letter is shifted forward by a fixed key s in the 26-letter alphabet. Case is kept, and spaces and punctuation are left untouched.

Encryption c = (p + s) mod 26 Decryption p = (c − s) mod 26 key space: s ∈ {0, …, 25}

05

Statistical cryptanalysis of the Caesar cipher

We use only the ciphertext and knowledge of the language. Since a Caesar shift moves the whole letter histogram, the right key is the shift that makes the ciphertext histogram look most like English. Three scoring methods are compared:

  • Most frequent letter. Assume the most common ciphertext letter is E, so s = cmax − 4.
  • χ² letter-frequency test. For each of the 26 shifts, decrypt and compute χ² = Σ (Oᵢ − Eᵢ)² / Eᵢ against English frequencies. The key is the shift with the smallest χ².
  • Bigram scoring (n-grams, n = 2). Score each candidate plaintext by the sum of the log-probabilities of its letter pairs (TH, HE, IN, …). The key is the shift with the highest score.

Exhaustive search is the frame for all three: there are only 26 candidates, and the statistics decide which one is English. The reference distribution is built from a corpus. A built-in English letter-frequency table is used by default, and you can paste any large English text below to rebuild it.

06

Effectiveness vs. ciphertext length

For each length L we take many random excerpts of English text with L letters, encrypt each with a random key, and check how often each method recovers the right key.

Effectiveness and limitations

  • With very short texts (under ~10 letters) the histogram is too noisy, and several shifts give readable or equally likely text. Success drops sharply, and "most frequent letter = E" is the first method to fail.
  • χ² uses the whole distribution, so it becomes reliable after a few dozen letters. Bigram scoring also uses letter order, so it is the most accurate on short texts.
  • All methods assume the plaintext is ordinary language with typical statistics. They fail on another language with a different distribution, on lists of names, codes or numbers, on deliberately unusual text (e.g. text written without the letter E), or on random-looking data such as compressed files.
  • The reference corpus must match the domain: technical text, informal chat and literature have slightly different frequencies.
  • In practice the decisive weakness is the key space. Even without statistics, a person can read all 26 decryptions; statistics just automates choosing the right one.
07

Attacking the restricted private key

An attacker sees the public key Q and the ciphertext. Because d ≤ 2b, they can search the key range. Every guess can be checked with certainty, since the right d satisfies d·G = Q. Once d is found, the message decrypts directly.

  • Exhaustive search. Walk G, 2G, 3G, … (one point addition per step) until the point equals Q. This takes up to 2b steps.
  • Baby-step giant-step (Shanks). Write d = i·m + j with m = ⌈√2b⌉. Store the "baby steps" j·G in a table, then take "giant steps" Q − i·(m·G) until one hits the table. This takes about 2·2b/2 operations, i.e. square-root time, at the cost of memory.

08

Discussion

Two very different attacks

The Caesar attack is statistical. It never checks a key for certain. Instead it exploits the fact that the cipher is deterministic and letter-wise, so the plaintext's language statistics pass straight through to the ciphertext. It needs enough ciphertext and a model of the language, and its answer is the most likely key, which can be wrong on short or unusual texts.

The ECC attack is a search, and it ignores statistics entirely. The randomized ciphertext reveals nothing about letter frequencies. But the public key gives the attacker a perfect test, d·G = Q, so each guess is either right or wrong with no uncertainty, and no ciphertext is needed to find d. The attack only succeeds because the key range is small: its cost grows with the number of possible keys (2b for brute force, 2b/2 for baby-step giant-step), not with the message.

Why it fails against a real key

With a properly generated key, d is uniform in [1, n − 1] with n ≈ 2²⁵⁶. Brute force needs about 2²⁵⁵ additions on average. The best generic algorithms (baby-step giant-step, Pollard's rho) still need about 2¹²⁸ ≈ 3.4 × 10³⁸ operations, and baby-step giant-step would also need memory for 2¹²⁸ points. At a trillion operations per second that is about 10¹⁹ years, far longer than the age of the universe. secp256k1 has prime group order and no known special structure, so no shortcut is known. The extrapolation table in section 07 turns the measured speed of this page into these numbers.

Other attacks, and where the weaknesses come from

From the restricted key space: exhaustive search, baby-step giant-step, and Pollard's kangaroo (designed for keys in a known interval, ≈ 2·2b/2 steps with very little memory). A precomputed table of d·G for all small d would even break every user of the scheme at once.

From the toy design itself, even with a large d:

  • Character-by-character encryption leaks the message length and word boundaries, and lets an attacker reorder, delete or replay characters.
  • Malleability. Adding k·G to C₂ changes m to m + k, so the ciphertext can be modified without detection. There is no integrity check or authentication.
  • The encoding M = m·G has only 256 possible values. If the ephemeral r is ever reused, C₂ − C₂′ = M − M′ = (m − m′)·G, and the attacker can find m − m′ in a 511-entry table. From there they recover the text with Caesar-style frequency analysis.
  • Weak randomness for r: if r comes from a small range or a predictable generator, r can be searched and r·Q removed without knowing d.
  • Real implementations also face side channels (timing and power of the scalar multiplication) and invalid-curve inputs. Real systems avoid these with hybrid schemes such as ECIES: ECDH for a shared secret, a KDF/hash, then authenticated symmetric encryption.
