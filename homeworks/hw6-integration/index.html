Riemann, Lebesgue and the normal CDF

Es 1 compares two ways to measure the area under a curve: slicing the domain (Riemann) and slicing the range and measuring preimages (Lebesgue). Es 2 computes one particular area that has no elementary formula, the standard normal CDF, and builds a fast method accurate to 13–14 significant digits, even far out in the tails.

Es 1

Riemann and Lebesgue integration

Two definitions of the integral

Riemann: partition the domain

Split [a, b] into n subintervals of width Δx = (b − a)/n, choose a tag ξᵢ in each one, and add up the rectangles. The function is Riemann-integrable when every choice of tags gives the same limit, which is equivalent to the upper sum U (sup on each piece) and the lower sum L (inf on each piece) squeezing together.

Rₙ(f) = Σᵢ f(ξᵢ) · Δx ∫ₐᵇ f dx = lim Rₙ(f) (n → ∞) Uₙ = Σᵢ supᵢ f · Δx, Lₙ = Σᵢ infᵢ f · Δx, integrable ⇔ Uₙ − Lₙ → 0

Lebesgue: partition the range

Split the values 0 = y₀ < y₁ < … < yₙ into levels. The set of points where f lands in a level, Eⱼ = f⁻¹([yⱼ, yⱼ₊₁)), is the preimage of that level, and m(Eⱼ) is its measure (its total length). This gives a simple function that approximates f from below. Summing the slabs instead of the columns gives the equivalent layer-cake formula, which is what we implement.

Lₙ(f) = Σⱼ yⱼ · m(Eⱼ), Eⱼ = { x : yⱼ ≤ f(x) < yⱼ₊₁ } ∫ f dm = ∫₀^∞ m({ x : f(x) > t }) dt (layer-cake formula, f ≥ 0)

The function t ↦ m({f > t}) is the distribution function of f. It is always non-increasing, and its shape, not the shape of f, decides how well the Lebesgue sums converge. For example, sin x on [0, π] has m({sin > t}) = π − 2 arcsin t, which has an infinite slope at t = 1 because sin is flat at its maximum.

The theorems we test

  • Lebesgue's criterion. A bounded function on [a, b] is Riemann-integrable if and only if its set of discontinuities has measure zero. f₃, f₄, f₆ qualify (one bad point), Thomae qualifies (discontinuous on the countable set ℚ), Dirichlet does not (discontinuous everywhere).
  • Agreement. If f is Riemann-integrable on [a, b], it is Lebesgue-integrable and the two integrals are equal. So on f₁–f₄, f₆, f₇ and T both numerical schemes must converge to the same number.
  • Monotone convergence. For f ≥ 0, if 0 ≤ fₖ ↑ f then ∫ fₖ ↑ ∫ f. Applied to the truncations min(f, H) as H → ∞, it lets the Lebesgue integral handle the unbounded f₅ directly: ∫₀¹ 1/√x dx = 2, with no "improper" limit needed in the definition.
  • Countable sets have measure zero. ℚ ∩ [0, 1] can be listed q₁, q₂, …; covering qₖ with an interval of length ε/2ᵏ covers ℚ with total length ε. Hence ∫ Dirichlet = 1 · m(ℚ ∩ [0,1]) = 0.

The algorithms

Five schemes are compared. All take a number of pieces n: subintervals for Riemann, levels for Lebesgue.

Lebesgue lowerrangeΣ Δt · m({f ≥ jΔt}) (= Σ yⱼ m(Eⱼ))n preimage measures

The levels run from 0 to the maximum H of f, so Δt = H/n. For the unbounded f₅ we integrate min(f, H) with H = √n, so the levels go higher as n grows. That is the monotone convergence theorem turned into an algorithm.

The hard part of Lebesgue is the measure of a preimage. Two ways to get it:

  • Analytic preimage: solve f(x) > t by hand. For example {x² > t} = (√t, 1], length 1 − √t. For sin x / x, which is decreasing on [0, π], the preimage is [0, xₜ) and xₜ is found by bisection. Exact, but needs the inverse of f, which a general method does not have.
  • Sampled preimage: evaluate f on a fine grid of N = 2¹⁷ points, sort the values once, then count how many lie above each level with a binary search. Generic, but every measure is now "number of grid points × grid width". The method is secretly built on a fine Riemann grid, and it can never be more accurate than that grid.
// Riemann: slice the domain
function riemann(F, n, tag) {               // tag = 0 (left) or 0.5 (midpoint)
  const h = (F.b - F.a) / n;
  let s = 0;
  for (let i = 0; i < n; i++) s += F.f(F.a + (i + tag) * h);
  return s * h;
}

// Lebesgue: slice the range, add up  Δt · m({ f > t })
function lebesgue(F, n, kind, measure) {    // measure(t, ge) = m({f > t}) or m({f ≥ t})
  const H  = F.unbounded ? Math.sqrt(n) : F.max;   // truncation min(f, H)
  const dt = H / n;
  let s = 0;
  for (let j = 1; j <= n; j++) {
    s += kind === "lower" ? measure(j * dt, true)     // classic lower simple function
                          : measure((j - 0.5) * dt, false);
  }
  return s * dt;
}

// Sampled preimage measure: sort N samples once, then binary-search each level
function sampler(F, N) {
  const h = (F.b - F.a) / N, ys = new Float64Array(N);
  for (let i = 0; i < N; i++) ys[i] = F.f(F.a + (i + 0.5) * h);
  ys.sort();
  return (t, ge) => (N - firstIndex(ys, t, ge)) * h;    // points above t × grid width
}

Pathological functions: where the two definitions part ways

Dirichlet function

Every subinterval contains rationals and irrationals, so sup = 1 and inf = 0 on each piece: Uₙ = 1 and Lₙ = 0 for every n. The tagged sum depends on the tags, so there is no Riemann limit. Below, "irrational tags" are ξᵢ = (i + ½)/n + √2/(4n), which are irrational because √2 is; the page tracks them symbolically as (rational part, coefficient of √2), since a computer cannot store an irrational number.

Lebesgue has no difficulty: for 0 < t < 1 the preimage {f > t} is ℚ ∩ [0, 1], a countable set of measure 0, so the layer-cake integral is exactly 0.

Why a computer cannot even see the problem

Every finite floating-point number is m · 2ᵉ, a fraction with a power-of-two denominator. So a naive isRational(x) must return true for every input, and any numerical method returns 1 for Dirichlet. Pick a number to see how it is really stored:

Thomae's function

Thomae is discontinuous at every rational but continuous at every irrational. The discontinuities form a countable set, so by Lebesgue's criterion it is Riemann-integrable. Upper sums go to 0: in a short interval every fraction has a large denominator q, so sup f = 1/q is small. Lower sums are 0. Lebesgue: for t > 0 the set {f > t} contains only fractions with q < 1/t, a finite set of measure 0, so the integral is 0.

Conclusions (Es 1)

  • Same limit for every Riemann-integrable function. On sin x, x², the step functions, |x − ½|, sin x / x and Thomae, all schemes converge to the exact value, as the agreement theorem predicts. The differences are only in how fast.
  • Riemann accuracy depends on the smoothness of f in x. Midpoint sums converge like n⁻² for smooth f (sin x, x², sin x / x), left sums like n⁻¹. The exception is when f(a) = f(b), as for sin x and |x − ½|: then the left sum equals the trapezoidal rule and also reaches order 2. A jump spoils every Riemann scheme back to n⁻¹, an error of about jump × Δx / 2 whenever the jump falls inside a piece. A corner like |x − ½| costs nothing, since the function stays continuous.
  • Lebesgue accuracy depends on the distribution function m({f > t}), not on f. Functions that take few values are easy for Lebesgue: f₆ is exact for every n, and f₃ is exact whenever a level lands on the value 1 (n a multiple of 3), otherwise its error is of order Δt. |x − ½| has the straight-line distribution function 1 − 2t, so midpoint levels are exact. Smooth functions can be harder: sin is flat at its top and x² flat at its bottom, which gives their distribution functions an infinite slope and lowers the midpoint-level order from 2 to about 1.5.
  • Unbounded functions behave differently. For 1/√x the left Riemann sum is undefined (f(0) = ∞), and the proper Riemann integral does not exist, only the improper limit. Lebesgue handles it directly by truncating at height H and using monotone convergence: the measure m({f > t}) = 1/t² is exact, and the only error is the cut-off tail ∫_H^∞ t⁻² dt = 1/H. With H = √n both approaches converge like n^(−½).
  • Efficiency depends on the function, but in general favours Riemann. On smooth functions, midpoint Riemann reaches an error of 10⁻⁶ with 4–8 times fewer pieces than midpoint Lebesgue, and for sin x / x each Lebesgue level costs a 60-step bisection. On step functions the roles reverse: Lebesgue is exact with a handful of levels, while Riemann needs about a million subintervals. But Lebesgue's speed relies on knowing the preimages. A general method has to sample f on a grid and sort the values, which costs more than the Riemann sum it is built on, and its error stops at the grid's own error (visible for |x − ½|).
  • Pathological functions show where Lebesgue wins in theory. Dirichlet has no Riemann integral (U = 1, L = 0 forever) but a clean Lebesgue integral of 0. Thomae is integrable in both senses, with value 0. Neither can be computed by sampling, because floating-point numbers are all rational: Dirichlet always reads as 1. These cases are settled by the measure theory, not by the numerics.
Es 2

Numerical computation of the normal CDF

Homework

Develop an efficient numerical method to compute the cumulative distribution function (CDF) of the standard normal distribution. Implement it, evaluate the CDF at several points and compare the results with a trusted numerical reference found on the web. Investigate the efficiency and accuracy of the implementation. Explain why the normal CDF cannot be expressed in terms of elementary functions (Liouville's theorem), how the error function erf gives an exact analytical representation, and why numerical methods are still needed. Explore numerical integration, series expansions and approximations based on erf.

The standard normal PDF and CDF

The standard normal distribution N(0, 1) has density φ and cumulative distribution function Φ. Φ(x) is the probability that a standard normal value is at most x, which is the area under the bell curve to the left of x.

φ(x) = e^(−x²/2) / √(2π) Φ(x) = P(Z ≤ x) = ∫₋∞ˣ φ(t) dt Φ(0) = ½ Φ(−x) = 1 − Φ(x) Φ′(x) = φ(x) Φ(x) → 1 as x → ∞

The constant 1/√(2π) makes the total area 1. The standard proof (Hogg, McKean and Craig, §3.4) squares the integral I = ∫ e^(−t²/2) dt and switches to polar coordinates: I² = ∫∫ e^(−(u²+v²)/2) du dv = ∫₀^(2π) ∫₀^∞ e^(−r²/2) r dr dθ = 2π. The extra factor r is exactly what makes the inner integral elementary. That trick only works over the whole line, not up to an arbitrary x, which is why Φ(x) itself has no formula.

The symmetry Φ(−x) = 1 − Φ(x) means we only ever need x ≥ 0. Computing the upper tail Q(x) = 1 − Φ(x) separately matters in practice: for x = 9, Φ(x) = 1 − 1.1 × 10⁻¹⁹, which a double rounds to exactly 1, so 1 − Φ(x) gives 0 and all information about the tail is lost.

Why Φ has no elementary formula: Liouville's theorem

Elementary functions are those built from rational functions with finitely many additions, multiplications, divisions, compositions, exponentials, logarithms and algebraic operations (roots). sin, cos, arctan are included, since they can be written with complex exponentials and logarithms.

Liouville's theorem (1835, modern form by Rosenlicht, 1972) describes exactly what an elementary antiderivative can look like. The case we need is:

Let f, g be rational functions, g not constant. Then ∫ f(x) e^(g(x)) dx is elementary ⇔ there is a rational function R(x) with R′(x) + g′(x) R(x) = f(x), and in that case ∫ f e^g dx = R(x) e^(g(x)).

Applying it to the bell curve

For e^(−x²/2) we have f = 1 and g = −x²/2, so g′ = −x. An elementary antiderivative exists only if some rational R satisfies

R′(x) − x · R(x) = 1
  • R cannot be a polynomial. If R has degree d ≥ 0, then x·R has degree d + 1 while R′ has degree d − 1 and the right side has degree 0. The leading term of x·R has nothing to cancel against, so the two sides cannot be equal. (R = 0 gives 0 = 1.)
  • R cannot have a pole. Suppose R = P/Q has a pole of order k ≥ 1 at some point c. Then R′ has a pole of order k + 1 at c, while x·R has a pole of order at most k and the constant 1 has none. The (k+1)-order pole of R′ cannot be cancelled, so again the equation fails.

So no rational R exists, and ∫ e^(−x²/2) dx is not elementary. If Φ were elementary, then (Φ(x) − ½)·√(2π) = ∫₀ˣ e^(−t²/2) dt would be an elementary antiderivative, a contradiction. This is a proof of impossibility, not a failure to find the formula. Computer algebra systems decide such questions with the Risch algorithm, which is built on the same theorem.

The error function: exact, but still not a number

Since no elementary formula exists, we name the missing antiderivative. The error function and its complement are

erf(z) = (2/√π) ∫₀ᶻ e^(−t²) dt erfc(z) = 1 − erf(z) = (2/√π) ∫_z^∞ e^(−t²) dt

Substituting t = u/√2 in the definition of Φ gives the exact representation

Φ(x) = ½ [ 1 + erf(x / √2) ] = ½ erfc(−x / √2) Q(x) = 1 − Φ(x) = ½ erfc(x / √2)

This is "exact" in the same sense that √2, π or sin(1) are exact: erf is a precisely defined function with known derivative, symmetry, series and asymptotic behaviour, so formulas involving it can be manipulated symbolically without error. But a name is not a value. To print digits, something still has to run an algorithm, and this is equally true of sin and exp: Math.sin is itself range reduction plus a polynomial approximation. Moreover, JavaScript has no built-in erf at all, so on this page every value of Φ is computed by code written here.

The algorithms come straight from the representations above. Integrating e^(−t²) = Σ (−1)ᵏ t²ᵏ / k! term by term gives a power series for erf. Integrating by parts in the tail integral gives a continued fraction. And rational approximations fitted to erf give fast fixed-cost formulas.

Numerical approaches

A. Numerical integration

Use Φ(x) = ½ + ∫₀ˣ φ(t) dt and a composite rule with n panels of width h = x/n. The trapezoidal rule has error O(h²); Simpson's rule fits parabolas and has error O(h⁴). Simple and general, but each evaluation of Φ costs n + 1 exponentials, and the tail is obtained as 1 − Φ, so its relative accuracy collapses for large x.

Trapezoid: ∫₀ˣ φ ≈ h [ ½φ(0) + φ(h) + … + φ((n−1)h) + ½φ(x) ] Simpson: ∫₀ˣ φ ≈ (h/3) [ φ(0) + 4φ(h) + 2φ(2h) + 4φ(3h) + … + φ(x) ]

B. Taylor series of erf (alternating)

erf(z) = (2/√π) Σₖ (−1)ᵏ z^(2k+1) / ( k! (2k+1) ) = (2/√π) ( z − z³/3 + z⁵/10 − z⁷/42 + … )

Converges for every z, but the terms alternate in sign and first grow to about e^(z²) before shrinking. Adding numbers of size e^(z²) to obtain a result of size 1 throws away about z² / ln 10 digits through cancellation: at x = 6 (z ≈ 4.24) roughly 8 of the 16 digits are lost, and at x = 8 the result is meaningless.

C. A positive series for Φ (Marsaglia, 2004)

Write Φ(x) = ½ + φ(x)·S(x). Differentiating gives φ = φ′S + φS′ = φ(S′ − xS), so S must satisfy S′ − xS = 1, the very equation Liouville showed has no rational solution. It does have a power-series solution, with only positive terms:

S(x) = x + x³/3 + x⁵/(3·5) + x⁷/(3·5·7) + … = Σₖ x^(2k+1) / (2k+1)!! Φ(x) = ½ + φ(x) S(x)

No cancellation inside the sum, each term is the previous one times x²/(2k+1), and about 40 terms give full double precision for |x| ≤ 2.5. Its weakness is again the tail: for large x, Q = ½ − φS subtracts two nearly equal numbers.

Partial sums of ½ + φ(x)·S(x) with N terms against the exact Φ. Every partial sum is elementary (a polynomial times e^(−x²/2)); only the infinite sum equals Φ.

D. Continued fraction for the tail (Laplace)

Q(x) = 1 − Φ(x) = φ(x) / ( x + 1/( x + 2/( x + 3/( x + 4/( x + … ))))) , x > 0

Evaluated from the bottom up with K levels, it computes the small tail Q directly, with no subtraction, so its relative accuracy stays high however small Q is. It converges quickly for large x and slowly near 0.

E. Rational approximation of erf (Abramowitz & Stegun 7.1.26)

erfc(z) ≈ (a₁t + a₂t² + a₃t³ + a₄t⁴ + a₅t⁵) e^(−z²), t = 1/(1 + 0.3275911 z), z ≥ 0 a₁ = 0.254829592, a₂ = −0.284496736, a₃ = 1.421413741, a₄ = −1.453152027, a₅ = 1.061405429

One exponential and a few multiplications, with absolute error below 1.5 × 10⁻⁷. Very fast, but fixed accuracy: its relative error in the tail grows without bound.

F. My method: hybrid series + continued fraction

Combine the strengths: use the positive series C where it converges fast and the continued fraction D where the tail is small, use symmetry for negative x, and always return both Φ(x) and Q(x) from the formula that computes the small one directly.

const SQRT_2PI = Math.sqrt(2 * Math.PI);
const pdf = x => Math.exp(-x * x / 2) / SQRT_2PI;

function normalCdf(x) {                       // returns { p: Φ(x), q: 1 − Φ(x) }
  const a = Math.abs(x), f = pdf(a);
  let p, q;
  if (a < 2.5) {                              // positive series: Φ = ½ + φ(a)·S(a)
    let s = a, term = a, k = 0;
    while (true) {
      k++;
      term *= a * a / (2 * k + 1);
      if (s + term === s) break;              // stop when the term no longer changes s
      s += term;
    }
    p = 0.5 + f * s;
    q = 0.5 - f * s;
  } else {                                    // continued fraction for the tail
    const K = Math.ceil(10 + 300 / (a * a));  // fewer levels needed as a grows
    let t = a;
    for (let k = K; k >= 1; k--) t = a + k / t;
    q = f / t;
    p = 1 - q;
  }
  return x >= 0 ? { p, q } : { p: q, q: p };  // symmetry Φ(−x) = 1 − Φ(x)
}

The switch point 2.5 and the number of levels K = ⌈10 + 300/x²⌉ were tuned by testing against the reference: at x = 2.5 the series needs about 40 terms and the continued fraction about 58 levels; at x = 8 only 15 levels are needed.

Conclusions (Es 2)

  • No elementary formula exists, provably. By Liouville's theorem, ∫ e^(−x²/2) dx would be elementary only if R′ − xR = 1 had a rational solution, and it has none. The normal CDF is therefore a genuinely new function.
  • erf makes Φ exact, not computable. Φ(x) = ½[1 + erf(x/√2)] is an exact identity, useful for algebra and for reusing library code. Getting digits out of it still requires an algorithm, as it does for every special function and even for exp and sin.
  • Integration rules work but are wasteful. Trapezoid and Simpson converge at their predicted rates (n⁻² and n⁻⁴), but need 100 to 1000 exponentials per value, which made them 10 to 100 times slower than the series methods in our timing test. Computing the tail as 1 − Φ also makes its relative accuracy degrade steadily with x, until it is lost completely by x ≈ 8.
  • The alternating erf series is a numerical trap. Mathematically convergent everywhere, it loses about z²/ln 10 digits to cancellation and gives garbage for x around 8. The same function written as Marsaglia's positive series is stable.
  • Fixed formulas are fast but limited. Abramowitz & Stegun 7.1.26 needs a single exponential and is the fastest method here, but its accuracy is capped at about 10⁻⁷ absolute, and far less in relative terms in the tail.
  • The hybrid method is accurate everywhere and cheap. Positive series for |x| < 2.5, continued fraction for the tails, symmetry for x < 0, and both Φ and 1 − Φ returned without subtraction. It matches SciPy to 13–14 significant digits across the whole range (worst relative error about 3.5 × 10⁻¹⁴, near x = ±2.5 where the two formulas meet), including tail probabilities as small as 10⁻²³, at a cost of one exponential and on average about 23 series terms or fraction levels. In our test it took about 100 ns per value, roughly four times slower than A&S 7.1.26 but over a million times more accurate in the tails.
